# 切片计划

产出两样东西：**一份计划**，和**一张切片卡**（每轮只做第一个切片）。不产出 PRD、不做任务树、不排期。

## 切片四条规则

1. **窄但穿透每一层**：一个切片同时碰到数据、接口、UI、验证所需的最小部分。禁止按技术层横切（先改协议的 → 再改接口的 → 最后改页面的），横切做完最后一项之前什么都验不了。
2. **做完能演示或能验证**：说不清「做完能看什么」就是没切到位，回上一步重切。
3. **装得进一个新鲜上下文窗口**：装不进就继续切，不靠「记住前面」硬撑。
4. **必要的预重构先做**：逻辑埋在特殊分支里、改不动时，先单独做一次纯搬移（不改变行为），再做功能。

## 计划里必须有的

- 顺序：哪个切片先做，为什么是它（依赖没理清不要并行）
- 每个切片一行：做什么 / 演示出什么
- 总「不做」清单：这次明确排除的相邻需求

## 切片卡（每轮填 5 行）

```
目标：<做完之后我能看到什么>
范围：<只改这几个文件>
不做：<明确排除的相邻需求>
证据：<在哪个接缝观察 + 截图 / curl / 命令输出>
回滚：<commit 点 或 还原方式>
```

「不做」这一行是防扩范围最有效的一句，必须写具体的东西，不写「保持范围克制」。

## 反例

- 按层拆：「先做 API，再做页面」——中间态无法验证
- 卡片写「完成后代码更清晰」——不是可观察的结果
- 一个切片动 8 个文件、或计划里出现「顺便把 X 也改一下」——都不是切片
