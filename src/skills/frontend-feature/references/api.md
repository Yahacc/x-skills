# 接口与数据边界

核心只有一条：**校验在边界做一次，往里一律信任。**

## 边界在哪

请求进来的第一段自有代码就是边界：route handler、server action、webhook 入口。在这一层把外部数据变成可信类型，往里传已校验的值。

边界之后还在反复判空，说明边界没做干净，而不是更安全。

## 返回形状固定

- 成功与失败用同一种外壳，调用方不必按状态码分支解析
- 不返回裸数组——以后要加分页就是 breaking change
- **不把数据库实体直接返回**：多一个字段就泄露一次，而且没人会发现
- 错误给机器可读的 code 加一句人能看懂的话，不返回堆栈

## 改返回值就是改契约

删字段、改字段语义、改类型、改状态码，都算对外行为变化。动手前先搜调用方；搜不到不等于没有（编辑器里看不到的外部消费者）。

## 校验只写一份

一次 schema 校验同时产出类型。手写 `if` 链再另写一份 TS 类型，两份之间迟早分叉。

## 反例（识别标志）

- 每个函数开头都 `if (!x) return` → 边界没做，靠下游兜
- `catch (e) { console.log(e) }` 后继续往下跑 → 吞掉错误比崩溃更难查
- 返回里出现 `passwordHash`、`internalNote` → select 写成了 `*`
- 前端和后台各写一份校验规则 → 不一致只是时间问题
- 加字段时改了 `select` 但没改返回类型 → 类型在骗人
