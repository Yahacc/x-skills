# 界面工程

这个文件只有一件事：**先把界面会出现的状态写全，再动手写结构**。命名、目录、样式方案一律以项目 `AGENTS.md` 为准。

## 状态先于结构

任何一个界面元素，先列出它在真实使用中会处于的状态，再决定 DOM 怎么写：

- 空（没有数据）、加载中、出错、只有一条、多到溢出
- 长文本 / 极短文本、图片缺失或比例不同、数字是 0 或特别大
- 慢网、重复点击、首屏之前

漏掉的状态不会消失，它会以「白屏」「转圈不停」「布局炸了」的形式在用户那里出现。**只做正常路径，等于只做了五分之一。**

## 结构先于样式

语义标签 → 布局 → 视觉。顺序反了，之后每改一次视觉都要动结构。

- 能点的是 `button`，能跳的是 `a`，不是带 `onClick` 的 `div`
- 布局用 flex / grid，不用 margin 堆位置
- 颜色、间距、圆角从项目 token 取；确实需要新值时，说明为什么现有 token 不够

## 复用：先内联

判断依据是**语义是否相同**，不是长得像不像。长得像但会各自演化的两块，抽出来就是负担。

拿不准就先内联。写第二遍时你自然知道该抽什么，这比提前设计可靠。

## 反例（识别标志）

- 组件里五个 `useState` 布尔量 → 这是一个枚举，不是五个开关
- `className` 里出现十六进制色值 → token 没被用上
- 一上来建 `components/ui/` 全家桶 → 没有真实调用方的组件库
- 改样式时顺手重构了组件结构 → 那是另一个切片
