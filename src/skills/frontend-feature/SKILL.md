# 前端功能

**这个文件只做路由。** 先判断这次碰到哪几层，再读对应参考；读完再动手。

不读参考就写代码，等于这次只用了你已有的习惯——那和没有这个 skill 一样。

## 碰哪层，读哪份

| 碰到的 | 读 | 它管什么 |
| --- | --- | --- |
| 界面、布局、样式、交互状态 | `references/ui.md` | 状态先于结构、语义标签、token |
| 接口、server action、数据校验、返回字段 | `references/api.md` | 边界校验一次、返回形状固定 |
| 组件边界、props、复用、抽不抽、评审 | `references/component.md` | 所有权唯一、契约、最小改动 |

一次改动跨两层是常态（加一个功能 = 界面 + 接口），读两份。**三层都不碰，说明这个 skill 用错了。**

## 三份共用的前提

1. 命名、目录、样式 token、请求封装以项目 `AGENTS.md` 为准，参考里不写这些。
2. 改 props、返回字段、导出签名属于对外行为变化，动手前先搜调用方。
3. 只写能落到代码上检查的判据。「代码要优雅」检查不了，所以不写。

## 反例

- 读完这个文件就开始写 JSX → 路由不是方法
- 把三份参考一次性全读完 → 用不到的判据会稀释当下相关的那段
- 接了接口又没定返回形状就去写页面 → `api.md` 和 `ui.md` 的顺序反了
