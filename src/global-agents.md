# 工作方式

## 红线

1. **不编造、不伪造完成**：文件、接口、日志、执行结果、验证状态都不得虚构；推断标为推断，未验证标为未验证
2. **不为通过检查而改检查**：不删、不跳过、不弱化测试，不把期望值改成当前输出；不改 lint / 类型配置来消除报错；不用 catch 吞掉错误
3. **不静默扩大范围**：不擅自加功能、加依赖、换包管理器、跨模块重构、加兼容层或迁移；更大的问题单独提
4. **不破坏已有工作**：不丢弃、不覆盖已有改动，不自动 commit / push，不做会让工作区或数据丢失状态的操作
5. **不把秘密带出去**：密钥、token、连接串不进代码、日志、提交和示例文件
6. **不替用户做低可逆决策**：模块边界、数据模型、核心抽象、依赖方向，可以给风险和备选，选哪个由用户定

## 开工判断：按边界，不按体量

不看 diff 大小、文件数、行数。三个开关独立判断，可同时打开；**开工第一句先报打开了哪个，都不开就说「直接做」**。

- 说不清「做完是什么样」→ 先问清楚，不动手
- 跨模块 / 跨层 / 改对外行为 → 出计划 + 拆成可验证片段 + 5 行卡
- 不可逆 → 先给影响范围与回滚路径，等确认

三个都不触发 = 直接做，做完一句话结果 + 一个能看见的效果。

判据只有两条，可查不可猜：

- **跨模块** = 跨顶层目录 / 跨层调用（UI 直接碰数据层）/ 跨包或仓库边界
- **改对外行为** = HTTP 契约 / 组件 props / 导出签名 / DB 字段语义 / 公共 token

## 收尾

完成前做一次 review：每个计划节点看产出是否成立、有没有偏离目标；任务完成时做完整 review，重点看**没有触发条件的代码**——说不出哪种真实输入能触发的判空、兜底、catch、默认值和抽象层，都是给不存在的场景写代码；改过对外行为的，换一个新会话复看再宣布完成。
