# 个人 Vibe Coding 系统

两份常驻 + 六个按需 skill。**这是源文件，不自动写入任何工具配置**——装到哪、装不装，由你决定。

## 常驻

| 文件                      | 干什么                                    | 装到哪                     |
| ------------------------- | ----------------------------------------- | -------------------------- |
| `global-agents.md`        | 适用范围 / 核心原则 / 工作流 / 沟通与边界 | 用户级配置（所有项目生效） |
| `project-agents.md`       | 项目的栈、命令、证据、禁改区、坑          | 目标项目根 `AGENTS.md`     |
| `project-agents-guide.md` | 上面那份每段怎么写                        | 只读，不装                 |

全局只写跨项目都成立的行为。「这个项目怎么跑」一律进项目那份——写进全局，就是所有项目一起错。

## 按需

| skill               | 什么时候触发                    |
| ------------------- | ------------------------------- |
| `frontend-feature`  | 页面、组件、样式、接口          |
| `y-media`           | 图片、视频生成编辑，按 Provider |
| `topic-to-video`    | 主题直出抖音竖版视频            |
| `work-log`          | 流水账 → 汇总明细 → 存 IMA      |
| `baby-name-advisor` | 取名、乳名、双语名              |
| `sansheng-liubu`    | 多角色评审、重大决策、一人公司  |

参考型（`frontend-feature`、`baby-name-advisor`）只做路由，判据在 `references/`；流程型（`topic-to-video`、`work-log`）步骤即内容，压不动；`y-media` 一个 brief 命中一个 flow。

`sansheng-liubu` 略特殊：步骤即内容，但真执行靠 `workflow/` 下的脚本（9 个角色 + 状态机），SKILL.md 只写契约与判据——脚本里的角色文本是这套制度的全部，改流程要改脚本、不要改 SKILL.md 的描述。

`frontend-feature` 按界面 / 接口 / 组件拆成 `ui.md`、`api.md`、`component.md`，不拆成三个独立 skill——那样三个 description 会抢同一次触发。

遗留冲突：`y-media` 与 `topic-to-video` 都命中「生成视频」，靠模型自己判。收敛方向——前者降级成 recipe，或收紧后者的 description。

## 装

1. **全局**：装 `global-agents.md`。只维护这一份，别处引用，不复制内容。
2. **项目**：`project-agents.md` 复制到目标项目根改名 `AGENTS.md`，占位符填完——留空比没有更危险。
3. **技能**：整目录复制，`references/`、`scripts/`、`core/`、`providers/` 一起拷。只拷 `SKILL.md` 得到的是只会讲流程的空壳。

## 验

新开一个会话问两件事：「上下文里没写的信息，该自己查还是先问我」「改完代码先跑什么」。答成「都先问你」或「一律跑全量测试」= 没装好，或被项目级配置盖掉。

再跑一个真实的小改动，看它是不是先读文件再改、报验证时没跑的算不算通过。**配置不验证等于没装。**

## 改

- 删规则只看一条：**删掉之后模型行为不变** → 立刻删。
- 加规则也只看一条：**它会改变模型在真实场景里的选择吗**；不会就只是倾诉，不写。
- 长度不设指标。长是因为要说的事多，短是因为重复少——压长度只靠去掉重复和不可判定的句子，不靠删掉必要的判断。
- 事实只写「这里和别处哪里不一样」。
